# 超星答题助手 · 自建 LLM 题库

> 作者 **AstonKrss** · 项目主页 <https://github.com/AstonKrss/xuexitongScriptLLM>

用你自己的大模型 API 自动作答超星章节测试和作业，并按课程任务清单自动刷视频（1 倍速真实播放）、文档、切换下一节。先用众包题库兜一层（默认已内置），查不到再落到模型；答案本地缓存，同一道题只花一次 token。

## 安装

1. 安装脚本管理器：推荐 [脚本猫](https://docs.scriptcat.org/)，Tampermonkey / Violentmonkey 也可以。
2. 新建脚本，把 `dist/chaoxing-llm-quiz.user.js` 全文粘进去保存。
3. 首次在大模型接口域名上发请求时，脚本管理器会弹窗询问是否允许，点**总是允许**。
   （脚本头部写的是 `@connect *`，因为你填的接口地址不固定，没法预先声明。）

## 配置

打开任意超星答题页，右下角会出现一个齿轮按钮 → 点开 → **设置**。

### 1. 选服务商

面板里有 7 个预设，选中后会自动填好接口地址和模型名：

| 服务商 | 适合谁 | 备注 |
|--------|--------|------|
| **DeepSeek** | 大多数人 | 中文选择题稳，价格低 |
| **智谱 GLM** | 追求效果优先的 | 默认 `glm-5.3` |
| **阿里百炼** | 有阿里云账号的 | 走 OpenAI 兼容模式 |
| **Kimi** | 有 Moonshot key 的 | 不支持 JSON 模式，走提示词约束 |
| **OpenCode Zen** | 已有 Zen key 的 | ⚠️ 只有 GLM/Kimi/Big Pickle 这类能用，GPT 和 Claude 走别的协议，填了会 404 |
| **OpenAI** | 有网络条件的 | 国内需自备网络环境 |
| **自定义 / 中转站** | 用中转站的 | 填 `https://xxx.com/v1` 或完整地址都行，脚本会自动补路径 |

### 2. 填 API Key 和模型名

各家控制台位置：

- DeepSeek：platform.deepseek.com → API Keys
- 智谱：open.bigmodel.cn → 密钥管理
- 百炼：bailian.console.aliyun.com → 密钥管理
- Kimi：platform.moonshot.cn → API Key

Key 只存在浏览器的脚本存储里，不会发到除你自己填的那个接口以外的任何地方。

**不知道模型名怎么写？点「拉取模型」。** 脚本会请求 `{base_url}/models` 把可用模型列出来，选一个即可。中转站的模型 ID 通常带前缀（如 `deepseek-ai/DeepSeek-V4.1-Flash`），靠猜基本猜不中。

### 3. 选请求格式

| 格式 | 请求打到哪里 | 什么时候用 |
|------|--------------|-----------|
| OpenAI 兼容 | `POST {base}/chat/completions` | 默认。绝大多数厂商和中转站 |
| Anthropic Messages | `POST {base}/messages` | 只提供 Claude 格式的网关 |

判断方法很简单：先用 OpenAI 试，报 404 且确认地址没写错，再换成 Anthropic。

### 4. 点「测试连接」

会真的发一个极短请求（问模型"中国的首都是哪座城市"），一次性验证地址、密钥、模型名、域名授权四件事。**结果显示在按钮下方**，成功会带上模型的实际回复和耗时，失败会给出下一步该改什么（比如"先去掉 JSON 模式"或"用拉取模型核对 ID"）。

如果报 400 且提示 `response_format` 相关，把「使用 JSON 模式」的勾去掉——有些接口不支持这个参数。

### 5. 题库优先（默认开启，已内置）

默认就是**先查题库，查不到再用模型**。题库给的是标准答案，比推理准，也不花 token。

内置的是原脚本（unrival 超星小助手）用的那家众包题库，地址和 token **已经填好，装上即可用**：

| 字段 | 值 |
|------|------|
| 题库接口地址 | `https://cx.icodef.com/wyn-nb?v=4` |
| Token | 已内置 |

面板里勾着「使用内置题库」时，这两个输入框是只读的——避免手滑改一个字符导致整轮静默不查。想换成自己的接口，取消这个勾即可。

三个细节：

- **会同时用「解码后的文字」和「加密态原文」各查一次**。因为题库若是从页面抓取众包来的，里面存的可能是乱码原文，用正常文字反而查不到。
- **题库答案必须能匹配上页面上的真实选项才采用**。对不上说明题库里是另一版题目，会丢弃并改走模型。
- **接口连续失败两次会自动停用**，避免每道题都白等超时。日志里会显示「题库命中 N 题」。

如实说明：内置的是**别人维护的公共凭据**，可能随时被限流或吊销；而且它是查表不是推理，冷门课和新出的专题大概率没有收录。查不到时自动落到模型，不影响使用。


### 6. 答题策略（默认值一般不用改）

| 项 | 默认 | 说明 |
|----|------|------|
| 并发数 | 3 | 调高更快但容易触发 429 |
| 单题超时 | 15000ms | 模型响应慢就再调大 |
| 最低置信度 | 0.5 | 模型没把握的题留空不填，交给你 |
| 覆盖率下限 | 100% | **这是"填了多少题"，不是"答对多少题"** |
| 逐题间隔 | 3~8 秒 | 模拟人类作答节奏 |
| 最短作答 | 题数 × 25 秒 | 20 题 = 8 分 20 秒，不足则等待后才提交 |
| 填完之后 | 自动保存 | 三档：只填 / 自动保存 / 自动提交，见下 |
| 本地缓存 | 开 | 同题第二次不再请求，直接复用 |

### 中转站配置示例

以 river.ai 为例（它同时支持 OpenAI 格式和 `/v1/models`）：

| 字段 | 填什么 |
|------|--------|
| 服务商预设 | 自定义 / 中转站 |
| 请求格式 | OpenAI 兼容 |
| 接口地址 | `https://api.river.ai/v1` |
| 模型名 | 点「拉取模型」后从下拉里选，例如 `deepseek-ai/DeepSeek-V4.1-Flash` |
| API Key | `rv_` 开头的那串 |

注意模型名要填**接口真实返回的 ID**。有些客户端配置文件里会带 `[1M]` 这类后缀，那是客户端自己的标记，不是模型 ID 的一部分，填进去会 404。

## 自动刷课

进入课程学习页（有章节目录那一页），点面板上的 **自动刷课**。

调度依据是**页面内嵌的任务清单**（knowledge/cards 的 `mArg` 数据，原刷课脚本用的同一份）——这一节有几个视频、几篇文档、有没有作业，清单里写得明明白白，不用等 iframe 慢慢渲染再摸黑猜：

1. 有视频 → 等播放器加载出来，**1 倍速真实播放**到结束；
2. 有文档 → 调超星自己的「阅读完成」接口标记；
3. 有作业 → 等作业页面出现（10 分钟内点开都来得及），**自动答题**，答完继续；
4. 任务点全部做完 → 点「下一节」，循环到最后一节。

### 作业没做完会停下来

「做完了」只认一种情况：**题目填满，并且已经提交或保存成功**。

以下都算没做完，刷课会**当场暂停**而不是跳到下一节（跳过去等于把整节作业绕掉）：

- 覆盖率不足（模型有题答不出）
- 设置成「只填不存」，答案还在页面上没落库
- 保存或提交失败
- 被超星判定「未完成」拦下来

停下来时日志会写明原因：

```
这一节作业结束：incomplete，覆盖率 50.0%，未保存
  原因：覆盖率 50.0% 未达 100%
这一节作业没做完，自动刷课已暂停 —— 继续往下会把它绕过去
```

处理完再点一次「自动刷课」就能接着走。

### 同一份作业只会做一次

用「首个题目 id + 题目数量」当指纹记在 `sessionStorage` 里。整页重载、来回翻也不会重复做；换一份卷子指纹就变了，会正常开做。

记在 sessionStorage 而不是 GM 存储——关掉标签就清空，不会第二天打开浏览器又去重做一遍昨天的作业。

### 它不做什么

- **不加速**。播放器就是 1 倍速，20 分钟的视频就等 20 分钟。
- **不伪造进度**。不调上报接口、不算签名、不改心跳。进度全部来自真实播放。

慢是代价，换的是服务端看不到任何异常：观看时长、上报节奏、心跳分布都是真的。

原脚本那套「算 enc 签名直接请求 reportUrl」的做法快得多，但一旦被判定，后果是**清空学习进度**——原脚本自己在代码注释里都写着「高倍速会被清空进度挂科，勿存侥幸」。

### 续跑

超星点目录节点常常整页重载。脚本用 `sessionStorage` 记一个标志，重载后 3 秒自动接上，不用你手动再点一次。关掉标签页标志就失效，不会第二天自己跑起来。

### 限制

- 「下一节」的定位靠五套兜底：专用按钮 → 文字匹配 → 新版目录树 → 老版 h4 → tabtags。如果你的页面结构都不匹配，点 **导出诊断** 发我。
- 视频自动播放可能被浏览器拦（需要用户手势）。被拦时日志会提示你手动点一下播放，脚本在你点完之后接手。
- 视频默认**静音**播放——这是浏览器允许自动播放的前提。需要声音自己开。
- 作业的「填完之后」设成「只填不存」时，答案不会落库，日志会提醒你。

## 使用

1. 进入章节测试页
2. 齿轮 → **只解析**，确认能正确识别题目和选项（这一步很重要，先看它抓得对不对）
3. 确认无误 → **开始答题**
4. 日志会逐题显示结果。全部填完后**会先等一段时间补足作答时长**（20 题约 8 分钟，日志里会显示剩余时间），再按覆盖率决定自动提交或保存
5. **提交后自己看一眼页面**，确认显示的是"已提交"而不是错误提示

> 关于为什么要等：脚本填 20 道题只要几十秒，真人要 6~12 分钟。作答时长是最容易计算的机器特征，等一等是为了让它落在合理区间。**不想等就点面板上的「跳过等待」**，或者把设置里「最短作答(秒/题)」调小、直接关掉。

### 填完之后做什么

设置里是一个三档下拉：

| 选项 | 脚本的行为 | 适合 |
|---|---|---|
| 只填好，我自己保存 / 提交 | 一个按钮都不点 | 想逐题检查一遍再手动交 |
| **自动保存，我自己提交**（默认） | 调页面保存，不提交 | 最稳：答案先存到服务器，你复核后再点提交 |
| 自动保存并提交 | 保存 + 提交 | 完全放手的场景 |

选第一档时答案**只留在页面上**，刷新或离开就没了，脚本会在日志里提醒你。

### 保存和提交是怎么做的

原脚本（unrival 那套）不点按钮，而是**直接调用页面自己的函数**：`noSubmit()` 保存、`submitCheckTimes()` 提交。这条路更可靠——不怕按钮文案改，也不经过确认框那一层。

现在也是这个优先级：

1. 先找页面自带的 `noSubmit` / `saveAnswer` / `submitCheckTimes` 等函数，有就直接调；
2. 找不到才退回去点「暂时保存」「提交」按钮。

有个之前踩过的坑值得记一下：**作业页在 iframe 里，这些函数挂在 iframe 的 window 上，不在顶层**。所以拦截确认框也必须装在 iframe 的 window 上——之前装在顶层，等于完全没拦住，超星弹「未完成」照样往下点确定。

### 提交前会先核对一遍

覆盖率是**脚本自己算的**（"我填了 60 题"），而超星判定"完成"看的是它自己的字段（每题的 `input[name="answer…"]` 值、填空题的 `#inpDiv` 内容）。两者不一致时，提交会被拒，页面还可能被重置——**填好的答案会一起消失**。

所以每道题填完都会先按超星的字段核一遍：对不上就自动重试一次（定制组件的点击是 toggle，状态判断失误会把已选答案点掉）。提交前再整体核对，发现漏题就：

- **不提交**，改为保存
- 日志写明「第 41-50 题在页面上没有留下答案，超星会判定为未完成」

超星弹「还有题未完成，确定要提交吗」时也**不会自动点确定**，而是取消并保存——强行提交只会被拒回 + 重置页面。

如果核对后发现 60 题全部识别不到答案，说明是超星改了字段名、核对方法失效，这时会跳过核对直接提交，不会把你卡死。

### 解析不出来怎么办

点 **导出页面结构**。它会把下面这些内容打到控制台、同时放进面板里的文本框（可以直接 Ctrl+A / Ctrl+C）：

- 页面基本信息、iframe 列表及是否可访问
- 前 3 道题的**真实 HTML**（截断到 1500 字符）
- 填空题候选输入框的识别情况

把这堆内容发我，我按你的实际页面写精确的选择器。

### 保存或提交没生效怎么办

点 **导出诊断**。它专门针对"点了但没反应"这种情况，输出：

- 当前文档所在 window 上挂了哪些函数（`noSubmit` / `submitCheckTimes` …）
- 页面上所有可见按钮的文字和标签
- 每道题的答案到底落在哪个字段（`input["answer…"]` 的值、填空的 `inpDiv` 内容、有没有选中样式）
- 自检结论：哪几题在页面上找不到答案

有了这份东西就能确定问题出在"函数名不对""按钮文字变了"还是"填空题没写进去"。

## 支持哪些页面结构

脚本按顺序尝试四套解析方式，命中即用：

| 顺序 | 依据 | 覆盖的页面 |
|------|------|-----------|
| 1 | `.Py-mian1` 类名 | 超星手机版作业页 |
| 2 | `.TiMu` / `.Zy_ulTop li` | 超星 PC 经典版作业页 |
| 3 | `【单选题】` 等题型文字 + 单字母标号 | 各类改版页面，**不依赖类名** |
| 4 | radio/checkbox 的 DOM 层级 | 其他标准表单结构的页面 |

第 3 套是关键的兜底：超星改版会换类名，但不会把「【单选题】」这几个字去掉。所以即使前两套都不认识，也大概率能靠它解析出来。

## 看不到面板怎么办

脚本在**所有匹配到的超星页面**都会挂一个右下角的齿轮（蓝色圆形按钮），不限于答题页。如果你看不到：

1. **先刷新页面**。装完脚本不刷新是不会生效的，这是最常见的原因。
2. 确认脚本管理器里这个脚本是**启用**状态（脚本猫/篡改猴的图标上会显示数字）。
3. 按 F12 打开控制台，搜 `超星答题助手`。正常情况下会有一行 `[超星答题助手] v0.3.x 已加载` 加当前网址。
   - 有这行但看不到齿轮 → 页面可能把元素覆盖了，告诉我网址
   - 没有这行 → 脚本没跑起来，多半是没启用或域名没匹配上
4. 齿轮上如果有**红点**，表示还没填 API Key。点齿轮 → 设置 → 填 key → 点「测试连接」。
5. 点「开始答题」提示"当前页面不是答题页"，说明脚本在**页面和它的 iframe 里**都没找到题目。章节测验通常就在课程学习页右侧的区域，先把测验打开再点。

## 关于字体加密

部分超星页面会用 `.font-cxsecret` 做**字体加密**：DOM 里存的字被替换成别的字，靠自定义字体渲染回正确字形。人看着是正常的，但脚本读到的是乱码，例如：

| DOM 里实际存的 | 屏幕上显示的 |
|---|---|
| 聚厩2035年建成文化强国战略廆标 | 聚焦2035年建成文化强国战略目标 |

**这会导致大量题目答不出来**——模型读到乱码，只能返回低置信度，脚本按规则跳过。

### 加密的原理

超星把**思源黑体**的「码位 → 字形」映射重新排了一遍：让 U+602E 这个码位指向「新」的字形。字体文件内嵌在页面里：

```html
<style id="cxSecretStyle">
@font-face { font-family: font-cxsecret; src: url("data:application/font-ttf;base64,...") }
</style>
```

关键点：**字形本身没改，只是被挂到了别的码位下。**

### 脚本怎么解

1. 从 `style#cxSecretStyle` 取出内嵌的 base64 TTF；
2. 用 Typr 解析 TTF，对页面上出现的每个字符取出 glyph 轮廓路径；
3. 轮廓路径 JSON 序列化后做 MD5，取末尾 8 位十六进制；
4. 拿这个哈希查内置的对照表，得到真实汉字。

因为哈希只取决于字形、与码位分配无关，所以**一张表通吃所有页面**——每页的字体文件都不同（大小、SHA-256 全变），但同一个汉字的哈希永远一样。

整个解码在**几十毫秒**内完成，不需要渲染任何字形，也不会卡界面。

### 已经用真实字体验证过

拿实际页面导出的 `cx-font.ttf`（26KB，112 个汉字）实测：

```
全字表扫描：112 个字形，其中 112 个能在对照表中找到（100.0%）
样本对照：  46 / 46 → 准确率 100.0%
```

解码前后的对比如下，可以直接看出效果：

| 解码前（DOM 原文） | 解码后 |
|---|---|
| 进入新时憿，我国憽憼走( )、懀色发展憾高质懁发展憻路。 | 进入新时代，我国坚持走( )、绿色发展的高质量发展道路。 |
| 懋时代以来，懐懎懀色发展方式步伐加快，懋懍源汽车产销量连续( )年居懏球襖位。 | 新时代以来，我国绿色发展方式步伐加快，新能源汽车产销量连续( )年居全球首位。 |

### 表对不上时会自己停下

如果超星换了字形（换了基础字体、或调整了轮廓），哈希就查不到表。这时候脚本会：

- 命中率低于 60%，或一个都没命中 → **判定失败、整轮停用解码**，绝不硬解；
- 日志写明「字形哈希匹配失败：N 个字一个都没查到」或具体命中率；
- 退回原始文本，由模型的上下文推断能力兜底。

**解错比不解更危险**：乱码你一眼能看出，而「霾」被改成近形的「麤」你根本发现不了。所以这里的取向是宁可不解。

### 怎么确认解码生效了

点 **「解码预览」**，它会打出「哪个字被还原成什么」以及几道还原后的题干：

- 通顺、没有「斸」「蓇」这类怪字 → 解码成功，直接答题
- 还是怪字连篇 → 表已经和当前字体对不上，脚本会自行停用

### 解码失败时也别慌

题干里被替换的字通常只占少数，正文还能读。提示词会告诉模型：这些生僻字是字体反爬造成的，请按上下文还原成通顺词句后再作答，能还原出来就给 0.6 以上的置信度。

所以**解码失败 ≠ 答不出来**，只是准确率会低一些。这时候可以把「最低置信度」从 0.5 调到 0.3，覆盖更多题——代价是错答也会变多，自己权衡。

### 对照表从哪来

内置的 20902 条对照表是从公开的超星字体逆向研究里取得的（`tools/cx-glyph-table.json`，可用 `node tools/gen-table.js` 重新生成 `src/06-cx-table.js`）。它属于社区研究成果，**不是超星官方提供的东西**，也不保证永久有效。超星哪天换了基础字体，这张表就得重做。

脚本体积因此涨到约 490KB（表 226KB + 字体解析库 97KB），这是拿 100% 准确率换来的。

**如果日志里出现「字形哈希匹配失败」，说明这张表和当前字体对不上**（换字体版本、或超星改了字形）。这时候点 **「导出字体」**，会把页面内嵌的 `.ttf` 存到下载目录；拿到那个文件就能重建对照表。

## 关于 iframe

超星的章节测验常常渲染在课程学习页内部的 iframe 里（页面地址看着像 `mycourse/studentstudy`，但题目在那个 iframe 中）。脚本会自动穿透同源 iframe 找到题目，界面上只有一个悬浮球，由顶层统一驱动。

如果 iframe 是跨域的（极少见），顶层看不到里面的内容，脚本会在那个框架里单独挂一个面板。

如果你用的域名不在下面这些里，告诉我，我加进去：

```
*.chaoxing.com  chaoxing.com  *.edu.cn  *.nbdlib.cn  *.hnsyu.net  *.ac.cn
```

## 准确性说明

模型是"推理"出答案，不是查标准答案库。这个差别在两类题上很明显：

- 水课的选择题、判断题：基本没差别
- 专业课的计算题、有歧义的表述题：会错

所以脚本的设计取向是**宁可跳过也不瞎选**：

- 模型给的选项原文跟页面对不上 → 跳过（不按字母硬套）
- 置信度低于 0.5 → 跳过
- 多选题有一项匹配不上 → 整题跳过（少选即全错）

跳过的题会留在页面上空着，覆盖率不达标就不会自动提交，这样你能一眼看出哪些题需要自己看。

## 已知限制

- **分页作业只处理当前页**。日志会提示，翻页后再点一次。
- **简答题、论述题不支持**，遇到时不会自动提交。
- **提交按钮靠文案匹配**（"提交/交卷/提交作业"）。如果是纯图标按钮会找不到，日志会提示。
- **超星大幅改版可能让解析失效**。此时按下面的方法导出结构。
- **字体对照表可能过期**。如果超星换了基础字体，字形哈希就查不到，脚本会停用解码并在日志里说明，不会硬解出错字。

### 目录结构

```
src/

  00-core.js      工具函数、GM 封装、日志总线
  05-lib-typr.js  Typr 字体解析库（第三方，内联，勿改）

  35-bank.js      第三方题库查询
  40-parser.js    题目解析（适配器链 + 语义启发式）
  45-font.js      字体加密解码（解析字形轮廓算哈希）
  50-matcher.js   答案与选项的评分匹配
  60-cache.js     本地题库缓存（LRU）
  70-runner.js    并发取答案、串行填入、提交
```

### 校验解码是否还准

导出页面的字体（面板上的「导出字体」），然后：

```bash
node tools/verify-font.js ~/Downloads/cx-font.ttf
```

它会拿 `real-samples.json` 里的真实题面对照，输出「命中多少 / 准确率」，并打印解码后的整句题干方便肉眼判断。准确率 ≥ 90% 说明表还能用。

```bash
node tools/bench-font.js [字体路径]   # 各阶段耗时，回答「会不会卡」
```
